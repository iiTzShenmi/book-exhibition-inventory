# EXIS Full Audit Report

**Audit date:** 2026-07-18
**Scope:** Current EXIS repository only. Static review, local SQLite integration tests, a historical SQLite migration rehearsal, and local Chromium screenshots. Production was not modified or subjected to destructive testing.

## 1. Executive Summary

EXIS is a Flask monolith for book-exhibition search and title-to-cabinet inventory management. The current branch has strong baseline controls: server-issued CSRF, role-aware admin routes, security headers, Redis-required hosted rate limiting, strict cover-host validation, pinned runtime dependencies, audit logs, and CI gates.

This audit confirmed seven defects, including one **P1 data-loss risk** in a legacy SQLite schema migration. All seven have been fixed and covered by targeted tests. The overall residual rating is **Medium**, primarily because production configuration, offsite restore capability, PostgreSQL concurrency, and dependency advisory resolution were not executable from this checkout.

The current code intentionally models one logical title-location record, not an integer quantity. An inventory record is in stock, out of stock, active, or archived. Quantity-like legacy endpoints now reject unsupported requests rather than reporting a misleading success.

## 3. Architecture Summary

`app.py` creates the Flask app, configuration, limiter, CSRF/header middleware, schema helpers, backup helpers, and blueprint registration. The deployment path is Render -> Gunicorn -> Flask -> PostgreSQL; local development uses SQLite. `Procfile` runs `database.tools.db_tools init-db --no-sync-csv` before `EXIS_AUTO_INIT=0 gunicorn app:app`.

## 5. Security Findings

### EXIS-2026-001: Legacy SQLite quantity migration could silently lose all inventory rows

- **Category / severity / confidence:** Data integrity / P1 High / Confirmed
- **Affected file and route:** `app.py:538`; release migration command
- **Cause and evidence:** The migration rebuilt `inventory` without inserting the new non-null `in_stock` and `status` fields. Every reinsertion from the tracked historical snapshot failed, but the code logged warnings and printed success. The source snapshot held 720 inventory rows.
- **Impact:** A migration could finish with an empty inventory table while claiming success.
- **Fix:** `app.py` standardizes legacy state columns, builds a schema-constrained candidate table, verifies its row count before swapping it into place, and rejects a row-count mismatch. A failed candidate leaves the original table intact; interrupted first-rename recovery restores the original name. It uses static SQL only.
- **Regression status:** Covered by preservation and duplicate-candidate rollback tests. A rehearsal on the historical snapshot preserved **720 -> 720** rows and served `/` with HTTP 200.

### EXIS-2026-002: Existing databases lacked a `book_title.topics` migration; cover migration was SQLite-only

- **Category / severity / confidence:** Upgrade compatibility / P2 Medium / Confirmed
- **Affected file and route:** `app.py:664-683`, `app.py:1266-1294`, `app.py:1637-1668`; search/home pages
- **Cause and evidence:** Models referenced `topics` and `cover_link`, but an existing schema could lack those columns. The historical snapshot returned HTTP 500 before migration for these missing columns.
- **Impact:** Upgrades could fail search or cover rendering after deploy.
- **Fix:** Added idempotent inspector-backed cover and topics migrations for supported databases, invoked by both explicit initialization and the optional request-time maintenance path.
- **Regression status:** Covered by `test_schema_migration_adds_legacy_book_title_columns` and the historical snapshot rehearsal.

### EXIS-2026-003: Analytics endpoint changed state through GET

- **Category / severity / confidence:** HTTP/CSRF integrity / P2 Medium / Confirmed
- **Affected file and route:** `routes/api.py`; `static/js/base.js`, `static/js/search_results.js`; `/book_details/<title>`, `/api/track_view`
- **Cause and evidence:** Both `GET /api/track_view?title=...` and `GET /book_details/<title>` incremented `view_count`. GET is cacheable/prefetchable and must be safe.
- **Impact:** Third parties, caches, crawlers, or link previews could alter analytics without user intent.
- **Fix:** Details are now read-only. The analytics route is CSRF-protected POST only and rate-limited to 60/minute; a shared client helper records intentional search-card and modal opens.
- **Regression status:** Covered by `test_view_tracking_requires_post_and_csrf` and `test_book_details_get_does_not_change_view_count`.

### EXIS-2026-004: Replenishment trusted an arbitrary source cabinet and had two client submitters

- **Category / severity / confidence:** Authorization/business integrity / P2 Medium / Confirmed
- **Affected file and route:** `routes/inventory.py:559-635`, `static/js/base.js:1520-1600`, `static/js/admin_dashboard.js`; `/replenish/<title>`
- **Cause and evidence:** The backend checked the target display cabinet but not that the source was a reserve cabinet or matched the route title. Both base and admin scripts registered the same click handler, allowing duplicate confirmation and POSTs.
- **Impact:** A display record could be used as a reserve source; rapid clicks could produce a confusing success/failure sequence.
- **Fix:** The route verifies reserve type, title identity, source/target existence, and locks source/duplicate rows on PostgreSQL. One delegated handler remains, and admin refresh hooks are exposed for it. Book-card replenishment metadata now follows the same handler contract.
- **Regression status:** Covered by reserve-source and title-mismatch tests. PostgreSQL two-client locking remains a staging test item.

### EXIS-2026-005: Deleting a cabinet with archived inventory returned HTTP 500

- **Category / severity / confidence:** Data integrity / P2 Medium / Confirmed
- **Affected file and route:** `routes/inventory.py:316-333`; `DELETE /cabinets/<id>`
- **Cause and evidence:** The route blocked active rows only. Deleting a cabinet with archived history attempted to null a non-null foreign key and triggered a server error.
- **Impact:** Misleading failure, noisy logs, and possible loss of audit context if model cascade behavior changes.
- **Fix:** Deletion now refuses any cabinet that retains inventory history and returns a controlled 400 response.
- **Regression status:** Covered by `test_delete_cabinet_rejects_retained_archived_inventory`.

### EXIS-2026-006: Strict CSP disabled inline book-card actions

- **Category / severity / confidence:** Functional security / P2 Medium / Confirmed
- **Affected file and route:** `routes/api.py:248-321`, `routes/api.py:405-455`, `static/js/base.js:133-185`; book details/card UI
- **Cause and evidence:** The deployed CSP uses `script-src-attr 'none'`, while responses still contained `onclick=` controls.
- **Impact:** Admin edit/add-cabinet/close controls rendered but did not run under the intended CSP.
- **Fix:** Replaced inline handlers with `data-ui-action` controls handled through the existing delegated listener.
- **Regression status:** Covered by `test_book_card_uses_declarative_actions_under_strict_csp` and a DOM-sink/static scan.

### EXIS-2026-007: Operational backup data was committed despite ignore rules

- **Category / severity / confidence:** Data exposure / P2 Medium / Confirmed
- **Affected files:** `database/backups/inventory_20251126_025509.db`, `.csv`
- **Cause and evidence:** Git ignore rules do not affect already tracked files. The SQLite snapshot contained 720 inventory rows and audit data; it did not contain admin or invite rows in the sanitized inspection.
- **Impact:** Operational/business data was available to repository readers and remains in historical commits.
- **Fix:** Removed the two artifacts from the current Git index while retaining local ignored copies. Added explicit prevention criteria in `SECURITY_CRITERIA.md:37-53`.
- **Regression status:** Current-tree check complete. **Historical removal requires a separately approved `git filter-repo` rewrite and force-push.**

## 6. Inventory Business-Logic Findings

### EXIS-2026-008: Deprecated quantity parameters returned false success

- **Category / severity / confidence:** API correctness / P3 Low / Confirmed
- **Affected file and route:** `routes/inventory.py:385-496`; `/adjust`, `/add_book`
- **Cause and evidence:** EXIS no longer has quantity columns, but `delta >= 0` did nothing while returning success, and `amount > 1` was accepted but only one record was created.
- **Impact:** Integrations and operators could believe stock changed by an amount that EXIS cannot represent.
- **Fix:** `/adjust` accepts only `delta=-1` for archival removal; `/add_book` accepts only amount `1`. Unsupported requests return clear 409/400 errors without creating data.
- **Regression status:** Covered by `test_legacy_quantity_endpoints_reject_unsupported_changes`.

The move workflow has a title/cabinet unique constraint and performs source/duplicate locking on PostgreSQL. The modeled operation is a move or archival transition, not arithmetic subtraction/addition. This is atomic at the application transaction level, but should still be exercised with two concurrent PostgreSQL clients before a high-traffic event.

## 8. UI/UX Findings

### EXIS-2026-009: Hidden quick-guide control overlapped the mobile brand label

- **Category / severity / confidence:** UI regression / P3 Low / Confirmed
- **Affected file and page:** `static/css/exis_refresh.css:1127-1134`; mobile `/search`
- **Cause and evidence:** The generic `.hero-brand__action` display rule overrode `.u-hidden`, rendering a disabled action over the product title at 390px width.
- **Fix:** Added a component-specific hidden rule. Chromium full-page mobile verification shows the title, return link, search controls, result, and approved cover without overlap.
- **Regression status:** Covered by `test_disabled_quick_guide_control_stays_hidden_on_mobile`.

Usability observations: public search has a clear top-level task, search cards expose the title/location state, and the responsive one-column flow is usable at 390px. The first-visit announcement modal intentionally interrupts discovery; it should be retained only if it is operationally necessary during the event.

## 9. Accessibility Findings

- **Likely:** Modal overlays generally lack explicit dialog semantics, initial-focus placement, focus trap, and focus return. Escape handling exists for several modals, but it is not complete modal accessibility.
- **Likely:** Several visible labels are not associated with controls through `for`/`id`; native wrapping labels are fine, but unwrapped labels in filter and admin forms should be corrected.
- **Informational:** `lang="zh-Hant"`, visible focus styling, local fonts, non-color status text, and reduced-motion CSS are present.

## 10. Performance Findings

- **Informational:** Search caps direct results at 200 and has PostgreSQL search indexes/helpers. It has no pagination, so very broad searches need production query-plan and latency measurement.
- **Informational:** Static assets use a version token and a service worker. Dynamic book-detail responses use no-store headers.
- **Fixed:** Duplicate replenish handlers were eliminated, removing duplicate requests and UI refreshes.

## 11. Dependency and Deployment Findings

`requirements.txt` is now a small pinned runtime contract, with development and tool dependencies split. CI installs `requirements-dev.txt`, which includes the runtime contract, and runs compile, tests, pip-audit, Bandit, and DOM-sink checks. Dependabot is enabled weekly for pip security updates.

Current production header sampling returned CSP, HSTS, `X-Frame-Options: DENY`, `nosniff`, referrer/permissions policy, secure HttpOnly Lax session cookie, and no-store. This confirms headers on the sampled public response only; it does not validate secrets, Redis, database, account roles, or backups inside Render.

The `security_report_2026_0525.md` core remediation areas are present in the current code: server-issued CSRF, ProxyFix and required hosted Redis, aligned CI/runtime dependencies, CSV cell sanitization, no raw DB URL in `pg_dump` argv, offsite backup tooling, and DOM-safe rendering. Runtime configuration and restore drills remain operational verification items.

2. **P2, Not Testable here:** Restore an offsite dump into a non-production Postgres database quarterly and record the result.
3. **P2, Not Testable here:** Verify Render has `FLASK_SECRET_KEY`, `INVITE_CODE_PEPPER`, `REDIS_URL`, secure proxy configuration, and the release migration command.

6. **P3, Inconclusive:** Run `pip-audit` in CI or a network-stable build environment and act on any advisory output.
