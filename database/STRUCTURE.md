# Database Directory Structure

## Overview

This directory contains all database-related code, tools, backups, and temporary files.

## Directory Layout

```
database/
├── __init__.py              # Package initialization
├── models.py                # SQLAlchemy ORM models
├── services.py              # Service layer for database operations
├── README.md                # Database documentation
├── STRUCTURE.md             # This file
├── .gitignore               # Git ignore rules for database files
│
├── inventory.csv            # CSV import/export (one-time use, local dev)
├── inventory.db             # SQLite database (local dev only)
│
├── backups/                 # Database backups
│   ├── .gitkeep            # Keep directory in git
│   ├── last_auto_backup.json  # Metadata for last backup
│   └── *.db, *.csv, *.sql  # Backup files (not in git)
│
├── logs/                    # Temporary log files and reports
│   ├── .gitkeep            # Keep directory in git
│   ├── titles_not_in_csv.txt      # Titles missing from CSV
│   └── book_csv_missing.txt       # Books missing from CSV
│
└── tools/                   # Database maintenance scripts
    ├── db_tools.py         # Main CLI tool (check, dedupe, purge-null, etc.)
    ├── local_db_sync.py    # Sync local SQLite to PostgreSQL
    ├── local_db_upload.py  # Upload local data to cloud
    ├── cloud_db_download.py # Download cloud database
    ├── drop_quantity_columns.py # Migration script
    ├── drop_book_csv_missing.py # Compatibility shim
    │
    └── reports/            # Generated diagnostic reports
        ├── .gitkeep       # Keep directory in git
        ├── duplicate_titles.tsv
        ├── orphan_inventory.tsv
        ├── malformed_topics.tsv
        └── null_titles.tsv
```

## File Categories

### Core Files (Version Controlled)
- `models.py` - Database schema definitions
- `services.py` - Business logic layer
- `tools/*.py` - Maintenance scripts
- `README.md`, `STRUCTURE.md` - Documentation

### Data Files (Not in Git)
- `inventory.db` - Local SQLite database
- `inventory.csv` - CSV import/export file
- `backups/*` - All backup files
- `logs/*` - Temporary log files
- `tools/reports/*` - Generated reports

### Temporary Files
All `.txt` files in `logs/` are temporary and can be safely deleted:
- `titles_not_in_csv.txt` - Generated by sync operations
- `book_csv_missing.txt` - Generated by check operations

## Maintenance

### Cleanup Old Backups
```bash
# Keep only last 7 days of backups
# (Manual cleanup recommended)
```

### Cleanup Reports
```bash
# Reports are regenerated on each check
# Safe to delete anytime
rm database/tools/reports/*.tsv
```

### Cleanup Logs
```bash
# Log files are temporary
# Safe to delete anytime
rm database/logs/*.txt
```

## Best Practices

1. **Backups**: Keep backups organized by date. Old backups can be archived or deleted.
2. **Reports**: Generated reports are temporary - regenerate as needed.
3. **Logs**: Log files are temporary - safe to delete after reviewing.
4. **CSV/DB**: Local files are for development only. Production uses PostgreSQL.

## Git Ignore Rules

The `.gitignore` file ensures:
- Database files (`.db`, `.sqlite`) are not committed
- Backup files are not committed
- Temporary files (`.txt` in logs) are not committed
- Generated reports are not committed
- Python cache files are not committed
